# 实施清单与后续事项（青鹿直播 · 前端仓库）

本文面向 **项目负责人 / 农户培训 / 后端联调**：汇总 **你需要亲自做的事**、**本仓库已覆盖的部分**，以及与后端商定后要改的 **配置与接口**。

---

## 本仓库当前已具备（可减少重复劳动）

- Vue 3 控制台：弹幕列表（WebSocket）、OBS 用 **`/overlay`**（透明商品卡片）、**`/scene`**（数字人占位 + 商品卡片）。
- 商品卡片：**名称 / 产地 / 价格**；若商品带有合法的 **`traceUrl`（http/https）**，卡片上会显示 **二维码**，便于观众扫码打开外链（适合 OBS 画面捕获场景）。
- 示例商品数据：未配置 API 时使用本地 `MOCK_PRODUCTS`。
- 推流说明与脚本示例：见 [`streaming/README.md`](../streaming/README.md)。

---

## 你需要亲自完成的事（农户与运营侧）

### 1. 环境与启动前端

1. 安装依赖：`npm install`
2. 复制环境变量：将项目根目录 [`.env.example`](../.env.example) 复制为 `.env`，按下面「环境变量」一节填写。
3. 本地验证：`npm run dev`，浏览器打开控制台、商品页、`/overlay`、`/scene`（带 `?productId=`）检查展示是否正常。
4. 生产构建：`npm run build`，将 `dist` 部署到 **HTTPS**（或局域网固定访问地址）；OBS 浏览器源里的地址必须是 **观众/主播能稳定访问的完整 URL**。

### 2. OBS + 直播平台（主推路径）

与 [`streaming/README.md`](../streaming/README.md) 一致：

1. OBS 中添加 **浏览器源**，URL 使用直播控制台里复制的 **`/overlay` 或 `/scene` 地址**（含 `productId`）；叠加层页需勾选 **允许透明**（仅 `/overlay` 必需）。
2. 按需合成 Live2D / 数字人窗口（若尚未接入真实 SDK，可先占位）。
3. OBS：**工具 → 虚拟摄像机 → 启动**。
4. 打开 **抖音 / 快手直播伴侣**，摄像头选择 **OBS Virtual Camera**，在伴侣内 **开始直播**。

说明：本前端里的「开始推流」按钮目前是 **占位**，不会代替伴侣开播或代替 OBS；真实「一键开播」若要做到伴侣内零步骤，需要平台侧能力或单独产品决策。

### 3. 商品与外链数据

- 在「商品」页或通过后端维护商品：确保 **`traceUrl`（或后续扩展的购买链接字段）** 为 **`https://...` 完整地址**，卡片才会出现二维码。
- 若暂时没有外链，不要填 `#`；填 `#` 或非 http(s) 链接时，卡片上不展示外链区。

### 4. 密钥与安全

- **推流地址、云厂商密钥、LLM/TTS 密钥** 等：**不要** 写进前端 `.env` 参与构建，也不要提交到 Git。
- 前端 `.env` 只放 **浏览器可知的公开项**：API 基址、WebSocket 地址（见 `.env.example`）。

## 与后端商定后要落地的内容

### 1. REST：商品

| 事项 | 说明 |
| --- | --- |
| **列表** | `GET /api/products`，返回数组；每项至少包含前端类型 [`Product`](../src/types/product.ts)：`id`、`name`、`origin`、`price`，可选 `traceUrl`。 |
| **单个** | `GET /api/products/:id`，供 `/overlay`、`/scene` 按 `productId` 拉取（与 [`fetchProductById`](../src/api/products.ts) 一致）。 |
| **失败策略** | 前端在请求失败或未配置 `VITE_API_BASE_URL` 时会回落到本地示例数据；生产环境应保证 API 可用。 |

**可选扩展（需前后端一起改）：**

- 若 **购买页** 与 **溯源页** 不同：后端增加 `purchaseUrl`（或类似字段），前端在 [`Product`](../src/types/product.ts)、[`ProductCardOverlay`](../src/components/ProductCardOverlay.vue)、[`ProductsView`](../src/views/ProductsView.vue) 中改为「卡片二维码优先用购买链接」。

### 2. WebSocket：弹幕 / 信令

| 事项 | 说明 |
| --- | --- |
| **地址** | 由 `.env` 中 `VITE_WS_URL` 指定（示例：`ws://127.0.0.1:8080/ws/danmaku`）。 |
| **消息格式** | 前端解析逻辑见 [`useDanmakuWs`](../src/composables/useDanmakuWs.ts)：支持 JSON，字段兼容 `user`/`nickname`、`text`/`content`、`ts`/`time`；或 `type === 'danmaku'` 且 `payload` 内含上述字段。 |
| **跨域** | 若前端静态站点与 WS 不同源，需后端网关支持 WebSocket 握手与鉴权策略。 |

**后续若要做「数字人自动回复」：** 需另行约定下行消息类型（例如：ASR 文本、LLM 回复文本、TTS 音频 URL、口型参数等），当前仓库 **尚未** 实现播放 TTS 或驱动 Live2D，仅接收弹幕并展示在控制台。

### 3. CORS 与部署拓扑

- 若浏览器从域名 A 访问 API（域名 B），后端需配置 **CORS** 允许来源与方法。
- 生产环境建议：**同源反向代理**（例如 Nginx 把 `/api`、`/ws` 转到 Spring Boot），可减少跨域配置复杂度。

### 4. 鉴权（若需要）

- 当前控制台与叠加页 **未接入登录**。若商品接口或 WS 需要 Token：需后端给出方案（Header / Cookie / 路径参数），再在前端 [`api/client.ts`](../src/api/client.ts) 与 WebSocket 连接处统一附带凭证。

## 环境变量与配置（和后端对齐后你要改的）

在项目根目录 `.env`（勿提交真实生产密钥到仓库）：

| 变量 | 用途 | 与后端商量什么 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | REST 基址，如 `https://api.example.com`（勿末尾多余 `/`） | 网关域名、是否带 `/api` 前缀；是否与前端同源代理 |
| `VITE_WS_URL` | 弹幕 WebSocket 完整 URL | 路径、是否 WSS、鉴权方式 |

参考模板：[`.env.example`](../.env.example)。

**OBS 复制出来的浏览器源 URL** 由 [`obsLinks`](../src/composables/obsLinks.ts) 使用 **`window.location.origin`** 生成，因此：

- 部署变更域名或子路径时，需在 **正在运行的前端站点** 上重新打开「直播控制台」并 **重新复制** `/overlay`、`/scene` 链接给 OBS。
- 若使用非根路径部署，需同时配置 Vite `base`（见 [`vite.config.ts`](../vite.config.ts)）与网关路由，保证 `/overlay`、`/scene` 可访问。

## 建议的后续迭代顺序（产品 / 技术）

1. **商品与外链**：后端落库真实商品；字段是否需要 **购买链接 / 溯源链接** 分拆；短链由后端生成则更利于二维码识别与统计。
2. **弹幕 → AI → TTS → 数字人**：后端编排 + 前端 **`DigitalHumanPlaceholder` 替换为 Cubism 挂载与音频播放**（需 SDK 授权与模型资产）。
3. **开播状态**：若需与伴侣或服务端状态同步，再定义接口并在控制台替换占位「开始推流」逻辑。
4. **合规与平台规则**：外链跳转、二维码内容、直播话术需符合各直播平台电商规范。
